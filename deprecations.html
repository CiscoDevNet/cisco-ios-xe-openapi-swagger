How these numbers are counted
Statements
Each status deprecated|obsolete line in the release's YANG files. A grouping counts once even when it is reused in many places.
Top-most nodes
Schema nodes (containers, lists, leafs, RPCs, notifications, choices, cases) where the status starts: the node is flagged but its parent is not. Flagged subtrees are counted once, at their top. This is the closest measure of "things to stop using".
All affected nodes
Every schema node whose effective status is deprecated or obsolete — its own status, or inherited from a parent, the uses/grouping that instantiated it, or the augment that added it. Groupings, augments and submodules are resolved by pyang, so a reused grouping is counted at each place it appears.
Definitions and other statements
Status on typedefs, identities, enum values, bits, groupings, features, uses/augment statements and SMIv2 aliases. They are not schema nodes; they are listed in each module's details.
Accuracy checks
Every status statement is found twice — by an independent tokenizer and by pyang's parser — and the two must agree exactly. Each one is then traced to the resolved schema tree or classified (definition, grouping never used, deviation module). Per-platform deviation modules are parsed but not applied, so nodes removed by a single platform's deviations still appear.
Changes since the previous release
Statements are matched by module, keyword, parent context and name (line numbers shift between releases). Newly means the statement existed before without that status; added means it is new and already flagged; now current means its own status line was dropped — it may still inherit a status from a parent. Node changes compare effective status by schema path; a new instance is a new copy of an already-flagged definition, for example a grouping reused under a new interface type.
